# Portfolio

Static site, no build step or framework — plain HTML/CSS/JS.

## Structure
- `index.html` — all four pages live in one file as `.page` divs, toggled by `showPage()` in `js/script.js`. Not real routing (no separate URLs per page yet). A `#music-gate` overlay, `<audio>` element, `#mini-player`, and `#lightbox` all sit outside the `.page` divs so they persist across page switches.
- `css/style.css` — all styles. Color/font values are set as CSS variables at the top of the file (`:root`).
- `js/script.js` — page switching (cross-fade via keyframes), scroll-reveal (`IntersectionObserver`) for the timeline, the music-gate carousel (preview/select/enter, mini player, melt transition), the blog accordion, and the project gallery's hover-video + lightbox behavior.

## Home hero
- Poster-style layout (`.poster-hero`/`.poster-*` in `css/style.css`): beige background, a bordered vertical-letter emblem (`.poster-emblem`) top-left spelling out "MOKSH" top-to-bottom, a `(2026) ▼` marker rotated below it, and `.hero-palette` positioned in the far top-right corner of the full hero panel (a direct child of `.hero-panel`, not nested in `.poster-wrap`, so it sits at the true page edge independent of the centered content column).
- There's no side photo anymore — `.poster-main`/`.poster-est`/`.poster-quote` are centered across the *full* hero width (`.poster-main{max-width:640px; margin:0 auto}`, `.poster-est`/`.poster-quote{left:0; right:0}` instead of the old `left:24px; width:64%` pair that reserved space for an image on the right) and shifted up (`padding-top:24%` on `.poster-main`, plus larger `bottom` offsets on the est/quote pair).
- `.hero-panel::after` is a `z-index:0` gradient (`transparent` → `var(--bg)` over the bottom 22%) that blends the beige panel into the next panel's near-black background — every piece of actual content sits at `z-index:1`+ (`.hero-palette` explicitly, everything else via the `.wrap`'s own `z-index:2`) so the gradient never covers anything.
- `.hero-palette` swatches use `style="background:var(--...)"` pointing directly at the site's `:root` custom properties — so it always reflects the live palette with zero maintenance. If you change a color in `:root`, this updates automatically; no hardcoded hex to keep in sync.
- The header (`<header>`) is beige (`var(--sage-bg)`) with dark text site-wide, so it blends seamlessly into the hero instead of reading as a separate bar — `.hero-panel{margin-top:-1px}` closes off any rendering seam at that boundary. The name has a soft multi-layer `text-shadow` in the hero's beige tone acting as a halo.
- No canvas/JS involved — it's pure HTML/CSS, absolutely positioned within `.poster-wrap` (except `.hero-palette`, positioned within `.hero-panel`). Stacks vertically on narrow screens (`max-width:720px`).
- `assets/hero/_style-reference-not-used.jpg` is a saved design reference (not linked from any page) — safe to delete once you don't need it for comparison anymore. `assets/hero/mountain-blueprint.jpg` and `assets/hero/clouds.jpg` are both unused now too (an earlier pass tried each as a side/background photo before settling on the plain beige panel) — safe to delete if you don't want to keep them around.

## Music gate
- A full pre-page shown before the site itself, on first visit each session (not tied to any specific page) — see `showMusicGate()` in `js/script.js`, called once at script load. Once a track is chosen or skipped, `sessionStorage['gate-decided']` is set and the gate won't reappear for the rest of the session.
- Base background is white/frosty (`.gate-bg-layer{background:linear-gradient(160deg,#fff,#eceae4)}`, blurred). Two stacked layers (`.gate-bg-layer-a`/`-b`) crossfade via opacity whenever the focused card changes, each set to that card's own `.gate-art` background — so the whole backdrop becomes a big blurred wash of the current track's artwork color, not a crisp copy of it (`updateGateBackground()` in `js/script.js`). A `.gate-bg-scrim` gradient (light at top, dark by the bottom ~35%) sits above both layers so text stays legible regardless of which color is currently showing.
- The carousel is a real carousel, not a coverflow row: cards get pulled horizontally back toward the center X position as they lose focus (`pulledX` in `updateCarouselTransforms()`, `js/script.js`) — so a card visibly slides behind the front one and gets mostly hidden there. The pull is eased (`Math.pow(pullT, 1.8)`) so the first card out still arcs outward and stays visible, then ramps up fast and is mostly tucked behind by ~2.5 cards away. Combined with `rotateY`, `translateZ`, shrinking `scale`, and fading `opacity`, recalculated every scroll frame.
- **Important structural detail**: none of that transform ever lands on `.gate-card` itself (the element with `scroll-snap-align:center`) — it all goes on an inner `.gate-card-visual` wrapper instead. Mutating `transform` on a snap-aligned element causes erratic, self-triggered re-snapping in some browsers (this was the cause of the "carousel scrolls by itself" bug) — keeping the snap target's geometry completely untouched by JS fixed it.
- Prev/next (buttons, and left/right arrow keys — `keydown` listener with `preventDefault` so the browser's native small-step arrow-key scroll can't fight the carousel) jump `scrollLeft` directly with `scroll-snap-type` temporarily disabled, then let a CSS transition on `.gate-card-visual` animate the visual result. This was the only approach that worked reliably — both a manual `requestAnimationFrame` tween and the browser's native `scrollTo({behavior:'smooth'})` got stuck fighting `scroll-snap-type: mandatory`, which snaps back any mid-flight scroll position synchronously.
- Trackpad/touch dragging is native browser scroll-snap (unaffected by any of the above, since it never touches `.gate-card`'s geometry); button clicks and arrow keys drive the same `scrollGateTo()` path described above.
- **Preview vs. select is intentionally separate**: each card's own ▶ button (or the pill bar's play/pause) previews that track through the shared `<audio>` element without committing to anything. Clicking "enter →" commits whichever track is currently centered — if it's already previewing, playback continues seamlessly into the mini player; if not, it starts fresh. `enter without sound` (the small link at the bottom) skips music entirely — but see below, skipping isn't final.
- 8 real tracks are wired up in `assets/audio/` (`.mp3` + matching cover art, same base filename — e.g. `leather-coat.mp3` / `leather-coat.jpg`). `updateGateBackground()` reads each card's `<img>` and sets it as a blurred `background-image` on the crossfade layer. To add or swap a track: drop the two files in `assets/audio/`, then add/edit a `.gate-card` block in `index.html` with matching `data-src`/`data-title`/`data-artist` and an `<img>` pointing at the art file — both the gate card and the mini player pull from the same `gateCards` list, so nothing else needs updating.
- **Changing your mind after skipping**: skipping doesn't just close the gate and forget about it — `showMiniPlayerNoTrack()` still shows the bottom-right pill, reading "pick a song" with the play/pause icon hidden (`.mini-player.no-track`). Clicking it calls `reopenMusicGate()`, which shows the same gate overlay again but bypasses the `sessionStorage['gate-decided']` check that normally stops it from reappearing. The gate is a pure overlay — closing it again doesn't touch page/scroll state, so picking a track (or skipping again) leaves you exactly wherever you were on the underlying page. `currentTrackIndex` starts at `-1` and only becomes a real index once a track is actually picked; that's what the pill checks to decide which state to render, including right after a page reload within the same session (`gate.hidden` stays `true` since the gate was already decided, so the pill needs to be shown separately for that path too).
- **Auto-advance**: `audio.loop` is `false` for real playback (it's only ever `true` transiently, for gate-preview clips) — an `ended` listener calls `playTrackAtIndex(currentTrackIndex + 1, true)` so the next track in `gateCards` starts automatically instead of the track just looping forever or stopping.

## Mini player
- The bottom-right widget is a pill by default (`#mini-player-pill`) and expands into a 240×340 square panel (`.mini-player.expanded`) on click — full album art, title/artist, and its own prev/play/next controls (`#mini-prev`/`#mini-play`/`#mini-next` in `js/script.js`), so the track can be changed after entering the site without going back to the gate. Click the ✕ or click anywhere outside the panel to collapse it back to the pill. In its `.no-track` state (see above) it never expands — clicking anywhere on the pill reopens the gate instead.
- `playTrackAtIndex()` and `currentTrackIndex` are the single source of truth for "what's playing" once inside the site — both the pill and the expanded panel read from the same `gateCards` array the gate carousel uses, so artwork/title/artist never fall out of sync between the two.
- The expanded panel also has a scrub bar (`#mini-seek`, the same restyled `<input type="range">` treatment as `#lightbox-video-seek`) so the background track can be seeked directly from the panel — `syncMiniSeek()` updates it on `timeupdate`/`loadedmetadata`, guarded with `!miniSeek.matches(':active')` so it doesn't fight the user's own drag mid-scrub, and its own `input` listener sets `audio.currentTime` to seek.

## Background-music ducking (forward-looking hook)
There's no real video/audio-snippet player on the site yet, but `js/script.js` already wires up the behavior for whenever one gets added: `document.addEventListener('play'/'pause'/'ended', ..., true)` (capture phase, since those events don't bubble) delegates to `duckBackgroundMusic()`/`resumeBackgroundMusic()` for *any* `<video>` or `<audio>` element on the page — pausing `#bg-audio` the instant another media element starts playing, and resuming it (from wherever it left off, since `.pause()`/`.play()` never touch `currentTime`) when that element pauses or ends. Muted elements are skipped (the project gallery's silent hover-preview `<video>` has no audio to conflict with), and the whole thing is a no-op if the user skipped the gate and never picked a background track (`currentTrackIndex < 0`) — there's nothing to duck or resume in that case. Because it's delegated rather than wired to specific elements, adding a real `<video>` or `<audio>` anywhere later needs no changes here.

## Blog page
- Each post row is now a `.blog-item` wrapping a `<button class="blog-row">` (the clickable title row) and a `.blog-drop` panel that expands/collapses via a `max-height` transition when clicked (see the "blog accordion" block in `js/script.js`). Only one post stays open at a time — opening one closes any other.
- `.blog-drop-placeholder` inside each is dashed-bordered placeholder text ("add your article here...") — replace that `<p>` with the real post content (plain HTML is fine) when you're ready to write.

## Brain dump page
- `#page-braindump` (`brain dump` in the nav, between blog and about) is a simple reverse-chronological list of `.dump-entry` blocks, each just a date label and a paragraph — meant for quick unfiltered thoughts rather than full posts.
- **Deliberately read-only and edit-only-by-hand**: there is no form, textarea, button, or any JS on this page — the only way to add or change an entry is editing `index.html` directly and pushing that change. That's intentional, not an oversight — a static site has no backend to authenticate "only me," so the actual guarantee comes from visitors never being given any input to begin with, not from a permissions check that could be bypassed. Adding a client-side "edit" UI later (even password-gated) would not really be private, since anyone can read the page's JS/localStorage in dev tools.
- To add a new thought: copy one `.dump-entry` block, put it at the top of `.dump-list` (newest first), and fill in the date + text.
## About page
Rebuilt as a **gallery-style, sectioned page** — one category at a time. `#page-about` sets its own strict black & white palette by overriding `--bg`/`--text`/`--muted`/`--line`/`--accent` locally (same scoping trick used elsewhere: it cascades to everything inside `#page-about` without touching the rest of the site).

The page opens on `.about-page-intro` — a plain, quiet block ("about — here are some things I like doing in my free time when I'm not coding") before the first category banner. It exists purely to give the page room to breathe and push the DJing banner down instead of opening straight into a full-bleed photo.

**Reusable per-category components** (class-based, not ID-based, so any number of categories can each use one):
- `.about-banner` — a full-bleed intro panel with a category photo as a CSS `background-image` (not `<img>`, so it degrades gracefully to a plain dark background if the file is missing, instead of a broken-image icon), a dark gradient overlay, and bold title text. Not click-gated — it's just the first full-height panel of each category; scrolling down reveals the rest normally (no scroll-hijacking, no click-to-reveal gate — every category's content is just visible on the page like the rest of the site).
- `.about-intro-copy--center` — centers a category's bio heading/paragraph when there's no side art to sit next to (DJing, Travel, Future).
- `.about-mix-grid` / `.about-mix-card` — a placeholder gallery grid (dashed-border glass cover, title, tag, disabled play button), reused as-is across categories for whatever the category's "browsable pieces" are (DJ mixes, film reels, etc.) — just the placeholder copy differs. Cards fade in on scroll via a shared `IntersectionObserver` (`.in-view`).
- `playSfx(name)` — a placeholder hook (`sfxFiles` lookup, safe no-op if a name has no file registered) wired to hover/click on gallery cards. Add real files under `assets/about/` and register them in `sfxFiles` in `js/script.js` to activate — no other code changes needed.

**Category 1 — DJing / Music Production** (`.about-category[data-category="djing"]`): banner = `dj-mixer.jpg`. The centered bio copy and the mix gallery are visible immediately (no click gate). What's unique to this category is the **audio-reactive border**: the entire section is framed by `.about-djing-border`, an absolutely-positioned pseudo layer whose `box-shadow` reads three CSS custom properties (`--djing-border-w/-a`, `--djing-glow`) off `.about-category.djing`. A single `requestAnimationFrame` loop in `js/script.js` rewrites those three properties every frame — no per-element DOM work, no canvas. While something is playing on the site's shared `#bg-audio` element, the values track the **peak of the bass/low-mid bins** (where kicks and snares live) with an *instant* attack and a hard release — the border jumps straight to its max on a hit and drops back to near-zero well before the next one, VU-meter style, swinging across its **full range** (width 0–16px, glow 0–140px, opacity 0–~1). While paused, it runs a slow full 0-to-1-to-0 idle sweep so it's never static. The underlying Web Audio graph (`initAboutAudioGraph()` — `AudioContext` → `createMediaElementSource(audio)` → `AnalyserNode`, reconnected to `ctx.destination` so it doesn't silently mute the site) is created lazily on the very first click anywhere on the page.

**DJing mixes → vinyl player**: each of the 6 mix cards shows a default `.mix-vinyl-icon` (grooves + label drawn with CSS gradients, no image) instead of a blank placeholder box, and carries `data-mix-src`/`data-fl-src`/`data-mix-title`/`data-mix-meta` (the first two empty until real files exist). Clicking a card doesn't clone anything — `flipInto()` in `js/script.js` physically moves that card's *own* `.mix-vinyl-icon` element into `#mix-player`'s slot, so it can later move back to the exact same card. `#mix-player` drives three states: `.opened` (the vinyl has grown in, centered — a "click to play" hint sits centered near the top of the overlay), `.playing` (added when the user clicks the vinyl a second time: the mix itself starts, ducking the background track via the same generic play/pause/ended hook Cinematography's reels use), then `.side-by-side` (2s into playing — the vinyl shrinks and shifts to the left while the FL Studio clip, which slid in from the right ~900ms into playing, grows into the spot the vinyl used to fill; both stay fully visible together as the overlay's two main components for as long as the mix plays — this never fades to a mini corner icon or lets the page become interactive again, it stays a modal "now playing" view). `.mix-player.opened .mix-player-vinyl` needs `pointer-events:auto` explicitly — the base rule sets `pointer-events:none` (so the vinyl doesn't intercept clicks while it's still a transparent 0-opacity placeholder before `.opened`); without that override on `.opened` too, a click meant to start playback would fall straight through to the backdrop underneath and close the player instead, reading as "clicking the vinyl just sends it back." A continuous spin animation on the vinyl was tried and removed — it visibly stuttered at the start of the animation (the FLIP-in transition and the spin keyframe fighting over the same `transform` property for a beat) before settling into a clean rotation, and wasn't worth the fragility once removing it was on the table anyway. Only the ✕ (or the backdrop, before playback starts) closes the player: audio/video stop, and the vinyl FLIPs smoothly back into the exact card it came from — the card is never left empty, it just briefly lends its vinyl out (`.mix-vinyl-borrowed` gives it a quiet dimmed look while it's gone). With no real mix/FL files attached yet, the whole sequence still plays; it just has nothing to actually play audio/video from.

**Category 2 — Cinematography** (`.about-category[data-category="cinematography"]`): banner = `comiccamera.jpg`. `.about-cinema-hero` is a real two-column grid (`grid-template-columns:1fr 1fr`) — bio copy on the left, `.about-cinema-roll` (the `cameraroll.jpg` film-strip photo, sized to fill its whole half of the section) on the right, no bounce/float animation. Because it's an actual grid rather than an absolutely-positioned overlay, the two can never overlap regardless of copy length; on narrow screens (`@media(max-width:720px)`) it collapses to a single centered column with the photo on top. The reels heading/lede below it are centered via `.about-mixes-wrap--center`. The two reel videos (`introduction.mp4`, `claude-cinematic.mp4`, both actually 1280×720) render at their **own natural size** now, not forced into any fixed-aspect box — `.about-mix-cover--video video{position:static; width:100%; height:auto; object-fit:contain;}` overrides the shared gallery's absolute-fill `object-fit:cover` treatment entirely. Two earlier attempts (square, then a forced `16:9` box) both still assumed a shape rather than reading the source, and either one could crop a clip whose real ratio didn't match — natural sizing can't crop, ever, regardless of what the source actually is. `.about-mix-cover--video` is a class on the cover element itself (not only an ancestor-scoped selector) so it survives being cloned into the lightbox, which strips away the original `.about-mix-card[data-video]` ancestor context. `#lightbox-media` gets a matching `.lightbox-media--video` class (set by `openLightboxWith()` based on whether the opened media contains a `<video>`) that also drops its fixed aspect-ratio for the same reason. The redundant ▶ overlay button that used to sit in the bottom-right corner of each thumbnail is gone — the whole card already opens the lightbox on click, and there's a real play/pause control inside it now. Playing a reel shows a glass "start/stop" bar (`#lightbox-video-controls` — backdrop-blur pill spanning the bottom edge of the video) with a play/pause button and a restyled `<input type="range">` seek bar (`#lightbox-video-seek`, synced via the video's own `timeupdate`/`loadedmetadata` events) instead of the browser's native video controls; it's a singleton element `openLightboxWith()` relocates into `#lightbox-media` only when a video is open, and stays hidden for photos. The controls bar also auto-hides — `showLightboxVideoControls()` fades it in on `mousemove`/`mouseenter` over `#lightbox-media` and resets a 2-second idle timer each time; once that timer fires it adds `.idle` (`opacity:0; pointer-events:none`, so a faded bar can't swallow a click), and moving the mouse again brings it right back — the same auto-hiding transport-controls pattern any video player uses.

**Category 3 — Travel** (`.about-category[data-category="travel"]`): banner = `travel-placeholder.jpg`. All 6 real places are filled in (Machu Picchu, Monaco, a bioluminescent bay in Puerto Rico, Volcán de Fuego in Guatemala, Petra, and the Pyramids of Giza), each with a real photo and a description written from the photo — `.about-travel-detail` holds that description text but is never shown in place (`display:none`); it's just where `openTravelViewer()` reads it from. `.about-travel-cover` has no border or background box anymore — photos sit flush in a `4:3` `object-fit:cover` grid frame (a fixed-shape grid still reads as a clean layout; the full uncropped photo shows in the expanded view instead). Clicking a card (or Enter/Space) opens `#travel-viewer`: the same `flipInto()` used by the DJing mix player moves the card's *actual* `<img>` — not a clone — into a larger, slightly left-of-center slot, a description panel slides in on the right, and the page's background switches to a heavily blurred, darkened wash of that same photo (`#travel-viewer-bg-blur`, `background-image` + `filter:blur(70px)`). Clicking the ✕ or the backdrop FLIPs the photo smoothly back into its own grid cell. `#travel-viewer-photo` (the fixed slot the photo animates into/out of) fades its own opacity in and out with `.opened` — it used to have no opacity transition of its own, so once the real `<img>` had already FLIPed back into its card, the now-empty slot's dark background sat there as a visible "stuck black box" for the ~600ms until the whole overlay force-hid itself.

**Category 4 — Future** (`.about-category[data-category="future"]`): banner = `future-placeholder.jpg`. A centered bio block (`.about-intro-copy--center`) with real copy — wanting to eventually start a company with co-founders, and treating networking/putting himself out there as the groundwork for that rather than a side project. No gallery here, so `.about-category[data-category="future"]` overrides the shared `100px 0 120px` category padding down to `56px 0 80px` — with just a heading and one paragraph, the default padding left the content looking lost in a lot of empty space.

`assets/about/README.md` documents the exact filenames each category expects. More categories can be added later as sibling `.about-banner` + `.about-category` pairs, reusing the same components above — nothing here assumes a fixed category count.

## Running locally
No build tools needed — open `index.html` directly in a browser, or serve the folder with any static server (e.g. `python3 -m http.server`) if you want `fetch`/relative paths to behave like production.

## Deploying
Live at **https://mokshpatel.vercel.app** — the Vercel project (`mokshpatel` in the `moksh-personal` team) is linked to this GitHub repo, so every push to `main` auto-deploys. Deployment protection (SSO gate) is disabled so the site is publicly viewable.
